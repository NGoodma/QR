# Telegram QR Bot

Присылаешь боту ссылку или любой текст, бот спрашивает формат, стиль и цвет и присылает QR-код файлом.

1. Ссылка или текст. Если в сообщении две строки, похожие на название сети и пароль Wi-Fi (пароль 8–63 символа, название до 32 байт), бот спрашивает: **📶 Код для подключения к Wi-Fi** или **📝 Просто текст**. Код для Wi-Fi записан в формате `WIFI:T:WPA;S:…;P:…;;`: камера телефона по нему сама предлагает подключиться к сети.
2. «Выберите формат»: **JPG** или **PNG**.
3. «Выберите стиль точек»: квадратные, скруглённые или круглые. У круглых три больших угловых квадрата остаются скруглёнными: угловые квадраты из точек не читают некоторые сканеры.
4. «Выберите цвет»: чёрный, белый, красный, оранжевый, жёлтый, зелёный, синий, фиолетовый, коричневый.
5. Дальше:
   - **PNG** приходит сразу, на прозрачном фоне;
   - для **JPG** бот спрашивает «Выберите цвет фона» (те же цвета, кроме цвета кода), потом «Углы фона»: прямые или скруглённые. В JPG нет прозрачности, поэтому срезанные углы белые. Если фон белый, вопрос про углы пропускается.

Текст влезает до 2300 латинских букв или около 1100 русских, длиннее бот не берёт. С версии 25 (примерно от 600 символов) бот предупреждает, что код плотный.

Если сочетание плохо сканируется, бот добавляет к файлу предупреждение. Так бывает, когда код светлый на тёмном фоне, когда цвета в оттенках серого различаются меньше чем на 80 из 255 (BT.601) или когда PNG светлый. Тест проверяет каждое сочетание цветов без предупреждения во всех стилях и с разными текстами сканером ZXing, а все стили ещё и OpenCV. Порог 80 подобран по замерам: формула контраста WCAG пропускала, например, фиолетовый на красном, который не читается.

Бот ничего не хранит. Меню отправляется ответом на сообщение с текстом, поэтому при каждом нажатии текст берётся из `reply_to_message`, а выбор хранится в `callback_data`: `q:<тип>:<формат>:<точки>:<цвет>:<фон>:<углы>`, ещё не выбранные поля пустые, например `q:t:jpg:ci:black::`.

## Хостинг

Vercel Hobby, бесплатно: Python-функция `api/telegram.py` принимает webhook от Telegram по адресу `https://qr-ngoodma.vercel.app/api/telegram`. Секрет webhook выводится из токена бота (SHA-256), поэтому отдельный секрет хранить не нужно. Как завести аккаунт и токены, описано в [docs/vercel-setup.md](docs/vercel-setup.md).

GitHub Actions (`.github/workflows/deploy.yml`) запускается на каждый push:
- `pytest`;
- в `main`, если заданы секреты `VERCEL_TOKEN` и `TELEGRAM_BOT_TOKEN`, запускает `scripts/deploy.py`: проект, переменная окружения, отключение защиты, деплой, адрес, webhook.

Скрипт можно запускать сколько угодно раз.

## Разработка

```bash
python3 -m venv .venv
```

```bash
.venv/bin/pip install -r requirements.txt pytest opencv-python-headless zxing-cpp
```

```bash
.venv/bin/python -m pytest -q
```

Тесты подменяют Telegram и проверяют все шаги, Wi-Fi, форматы, прозрачность PNG, цвет и углы фона JPG, предупреждения и то, что картинки реально сканируются (OpenCV и ZXing; без них эти тесты пропускаются).
